# ash_typescript

> Generate type-safe TypeScript clients directly from your Ash resources and actions, ensuring end-to-end type safety between your backend and frontend.

## Docs

### AshTypescript.Codegen (module)

Main code generation module for TypeScript types and schemas from Ash resources.

This module serves as the primary entry point for code generation. It delegates
to specialized submodules in `AshTypescript.Codegen.*` for specific tasks:

- `TypeDiscovery` - Discovers all types needing TypeScript definitions
- `TypeAliases` - Generates TypeScript type aliases for Ash types
- `ResourceSchemas` - Generates resource schemas (output and input)
- `TypeMapper` - Maps Ash types to TypeScript types
- `Helpers` - Shared utility functions

### AshTypescript.Codegen.ResourceSchemas (module)

Generates TypeScript schemas for Ash resources.

Uses a unified field classification pattern for determining how to generate
TypeScript definitions. The `classify_field/1` function categorizes fields
into types like :primitive, :relationship, :embedded, :union, etc.

### AshTypescript.Codegen.ResourceSchemas.field_category/0 (type)

Field categories for schema generation.

- `:primitive` - Simple types mapped directly to TypeScript
- `:relationship` - Ash relationships (has_many, belongs_to, etc.)
- `:embedded` - Embedded resources
- `:union` - Ash.Type.Union types
- `:typed_map` - Map/Keyword/Tuple with field constraints
- `:typed_struct` - Struct with fields and instance_of constraints
- `:calculation` - Complex calculations with arguments

### AshTypescript.Codegen.ResourceSchemas.classify_by_type/1 (function)

Classifies a field by its type, handling NewType unwrapping and array wrappers.

### AshTypescript.Codegen.ResourceSchemas.classify_field/1 (function)

Classifies an Ash field into a category for schema generation.

Handles relationships, calculations, and attribute types. Returns the field
category which determines how to generate its TypeScript definition.

### AshTypescript.Codegen.TypeDiscovery (module)

Discovers all types that need TypeScript definitions generated.

This module serves as the central type discovery system for the code generator.
It recursively traverses the type dependency tree starting from RPC-configured
resources to find all Ash resources and TypedStruct modules that need TypeScript
type definitions.

### Type Discovery - AshTypescript.Codegen.TypeDiscovery (module)

The discovery process handles:
- Ash resources (both embedded and non-embedded)
- TypedStruct modules
- Complex nested types (unions, maps, arrays, etc.)
- Recursive type references with cycle detection
- Path tracking for diagnostic purposes

### Main Functions - AshTypescript.Codegen.TypeDiscovery (module)

- `scan_rpc_resources/1` - Finds all Ash resources referenced by RPC resources
- `find_embedded_resources/1` - Filters for embedded resources only
- `find_field_constrained_types/1` - Finds all field-constrained types in resources
- `get_rpc_resources/1` - Gets RPC-configured resources from domains

### Validation & Warnings - AshTypescript.Codegen.TypeDiscovery (module)

- `find_non_rpc_referenced_resources/1` - Finds non-RPC resources referenced by RPC resources
- `find_non_rpc_referenced_resources_with_paths/1` - Same as above but includes reference paths
- `find_resources_missing_from_rpc_config/1` - Finds resources with extension but not configured
- `build_rpc_warnings/1` - Builds formatted warning message for misconfigured resources

### Path Tracking - AshTypescript.Codegen.TypeDiscovery (module)

During traversal, paths are tracked as lists of segments like:
- `{:root, ResourceModule}` - Starting point
- `{:attribute, :field_name}` - Attribute field
- `{:calculation, :calc_name}` - Calculation
- `{:aggregate, :agg_name}` - Aggregate
- `{:union_member, :type_name}` - Union member
- `{:array_items}` - Array items
- `{:map_field, :field_name}` - Map field

### Examples - AshTypescript.Codegen.TypeDiscovery (module)

# Get all types that need TypeScript definitions
    all_resources = TypeDiscovery.scan_rpc_resources(:my_app)
    field_constrained_types = TypeDiscovery.find_field_constrained_types(all_resources)

    # Get non-RPC resources with paths showing where they're referenced
    TypeDiscovery.find_non_rpc_referenced_resources_with_paths(:my_app)
    # => %{
    #      MyApp.InternalResource => [
    #        "Todo -> metadata -> TodoMetadata -> internal",
    #        "User -> profile_data"
    #      ]
    #    }

    # Build and output warnings for misconfigured resources
    case TypeDiscovery.build_rpc_warnings(:my_app) do
      nil -> :ok
      message -> IO.warn(message)
    end

### AshTypescript.Codegen.TypeDiscovery.build_rpc_warnings/1 (function)

Builds a formatted warning message for resources that may be misconfigured.

Returns a formatted warning string if any issues are found based on configuration settings,
or nil if everything is configured correctly.

Checks (based on configuration):
- Resources with AshTypescript.Resource extension but not in any typescript_rpc block
  (if `AshTypescript.warn_on_missing_rpc_config?()` is true)
- Non-RPC resources that are referenced by RPC resources
  (if `AshTypescript.warn_on_non_rpc_references?()` is true)

### Parameters - AshTypescript.Codegen.TypeDiscovery.build_rpc_warnings/1 (function)

* `otp_app` - The OTP application name

### Returns - AshTypescript.Codegen.TypeDiscovery.build_rpc_warnings/1 (function)

A formatted warning string, or nil if no warnings are needed.

### Examples - AshTypescript.Codegen.TypeDiscovery.build_rpc_warnings/1 (function)

iex> case TypeDiscovery.build_rpc_warnings(:my_app) do
    ...>   nil -> :ok
    ...>   message -> IO.warn(message)
    ...> end

### AshTypescript.Codegen.TypeDiscovery.scan_rpc_resources/1 (function)

Finds all Ash resources referenced by RPC resources.

Recursively scans all public attributes, calculations, and aggregates of RPC resources,
traversing complex types like maps with fields, unions, typed structs, etc., to find
any Ash resource references.

### Parameters - AshTypescript.Codegen.TypeDiscovery.scan_rpc_resources/1 (function)

### Returns - AshTypescript.Codegen.TypeDiscovery.scan_rpc_resources/1 (function)

This includes both embedded and non-embedded resources, as well as the RPC resources

### Examples - AshTypescript.Codegen.TypeDiscovery.scan_rpc_resources/1 (function)

iex> all_resources = AshTypescript.Codegen.TypeDiscovery.scan_rpc_resources(:my_app)
    [MyApp.Todo, MyApp.User, MyApp.Organization, MyApp.TodoMetadata]

    iex> # Filter for non-RPC resources
    iex> rpc_resources = AshTypescript.Codegen.TypeDiscovery.get_rpc_resources(:my_app)
    iex> non_rpc = Enum.reject(all_resources, &(&1 in rpc_resources))

    iex> # Filter for embedded resources only

### AshTypescript.FieldFormatter (module)

### AshTypescript.FieldFormatter.convert_to_field_atom/2 (function)

Converts a field name to an atom, applying the formatter for case conversion.

Unlike `parse_input_field/2` which tries to use existing atoms, this function
always creates an atom (using String.to_atom/1 for strings that aren't existing atoms).
Use this when you need guaranteed atom output for field selection.

### Examples - AshTypescript.FieldFormatter.convert_to_field_atom/2 (function)

iex> AshTypescript.FieldFormatter.convert_to_field_atom("userName", :camel_case)
    :user_name

    iex> AshTypescript.FieldFormatter.convert_to_field_atom(:user_name, :camel_case)
    :user_name

### AshTypescript.FieldFormatter.format_field_for_client/3 (function)

Formats a field name for client output, optionally applying resource/type-level
field_names mapping.

Use this when formatting field names for client consumption where the field
might have a custom TypeScript name via the `field_names` DSL option or the
`typescript_field_names` callback function.

### Examples - AshTypescript.FieldFormatter.format_field_for_client/3 (function)

iex> AshTypescript.FieldFormatter.format_field_for_client(:user_name, nil, :camel_case)
    "userName"

    iex> AshTypescript.FieldFormatter.format_field_for_client("already_string", nil, :camel_case)
    "alreadyString"

When a resource or type module is provided with `field_names`/`typescript_field_names` mappings
(e.g., `:is_active?` → `"isActive"`), the mapped string value is used directly WITHOUT
additional formatting.

Recursively processes nested maps and arrays to ensure all field names are properly formatted.

### AshTypescript.Rpc.Error (protocol)

Protocol for extracting minimal information from exceptions for RPC responses.

Similar to AshGraphql.Error, this protocol transforms various error types into
a standardized format with only the essential information needed by TypeScript clients.

### Error Format - AshTypescript.Rpc.Error (protocol)

Each implementation should return a map with these fields:
- `:message` - The full error message (may contain template variables like %{key})
- `:short_message` - A concise version of the message
- `:type` - A machine-readable error type (e.g., "invalid_changes", "not_found")
- `:vars` - A map of variables to interpolate into messages
- `:fields` - A list of affected field names (for field-level errors)
- `:path` - The path to the error location in the data structure
- `:details` - An optional map with extra details

### Example Implementation - AshTypescript.Rpc.Error (protocol)

defimpl AshTypescript.Rpc.Error, for: MyApp.CustomError do
      def to_error(error) do
        %{
          message: error.message,
          short_message: "Custom error occurred",
          type: "custom_error",
          vars: %{detail: error.detail},
          fields: [],
          path: error.path || []
        }
      end
    end

### AshTypescript.Rpc.FieldProcessing.FieldSelector (module)

Unified field selection processor using type-driven recursive dispatch.

This module mirrors the architecture of `ValueFormatter`, using the same
`{type, constraints}` pattern for type-driven dispatch. Each type is
self-describing - no separate classification step is needed.

### Design Principle - AshTypescript.Rpc.FieldProcessing.FieldSelector (module)

The key insight is that field selection and value formatting are parallel
operations - both traverse composite types recursively based on type information.
By using the same dispatch pattern, we achieve consistency and simplicity.

### Type Categories - AshTypescript.Rpc.FieldProcessing.FieldSelector (module)

| Category | Detection | Handler |
|----------|-----------|---------|
| Ash Resource | `Ash.Resource.Info.resource?(type)` | `select_resource_fields/3` |
| TypedStruct/NewType/CustomType | `typescript_field_names/0` callback | `select_typed_struct_fields/3` |
| Typed Map/Struct | Has `fields` constraints | `select_typed_map_fields/3` |
| Tuple | `Ash.Type.Tuple` | `select_tuple_fields/3` |
| Union | `Ash.Type.Union` | `select_union_fields/3` |
| Array | `{:array, inner_type}` | Recurse with inner type |

### AshTypescript.Rpc.ValueFormatter (module)

Unified value formatting for RPC input/output.

Traverses composite values recursively, applying field name mappings
and type-aware formatting at each level.

The type and constraints parameters provide all context needed - no separate
"resource" context is required because each type is self-describing:
- For Ash resources: field types come from `Ash.Resource.Info.attribute/2`
- For TypedStructs: field types come from `constraints[:fields]`
- For typed maps: field types come from `constraints[:fields]`
- For unions: member type and constraints come from `constraints[:types][member]`

### Key Design Principle - AshTypescript.Rpc.ValueFormatter (module)

The "parent resource" is never needed because each type is self-describing.
When we recurse into a nested value, we pass the field's type and constraints,
which contain all the information needed to format that value correctly.

### AshTypescript.TypeSystem.Introspection.unwrap_new_type/2 (function)

Recursively unwraps Ash.Type.NewType to get the underlying type and constraints.

When a type is wrapped in one or more NewType wrappers, this function
recursively unwraps them until it reaches the base type. If the NewType
has a `typescript_field_names/0` callback and the constraints don't already
have an `instance_of` key, it will add the NewType module as `instance_of`
to preserve the reference for field name mapping.

### Parameters - AshTypescript.TypeSystem.Introspection.unwrap_new_type/2 (function)

- `type` - The type to unwrap (e.g., MyApp.CustomType)
- `constraints` - The constraints for the type

### Returns - AshTypescript.TypeSystem.Introspection.unwrap_new_type/2 (function)

A tuple `{unwrapped_type, unwrapped_constraints}` where:
- `unwrapped_type` is the final underlying type after all NewType unwrapping
- `unwrapped_constraints` are the final constraints, potentially augmented with `instance_of`

### Examples - AshTypescript.TypeSystem.Introspection.unwrap_new_type/2 (function)

iex> # Simple NewType with typescript_field_names
    iex> unwrap_new_type(MyApp.TaskStats, [])
    {Ash.Type.Struct, [fields: [...], instance_of: MyApp.TaskStats]}

    iex> # Nested NewTypes (outermost with callback wins)
    iex> unwrap_new_type(MyApp.Wrapper, [])
    {Ash.Type.String, [max_length: 100, instance_of: MyApp.Wrapper]}

    iex> # Non-NewType (returns unchanged)
    iex> unwrap_new_type(Ash.Type.String, [max_length: 50])
    {Ash.Type.String, [max_length: 50]}

### AshTypescript.TypeSystem.ResourceFields (module)

Provides unified resource field type lookup.

This module centralizes the logic for looking up field types from Ash resources,
supporting attributes, calculations, relationships, and aggregates.

### Variants - AshTypescript.TypeSystem.ResourceFields (module)

- `get_field_type_info/2` - Looks up any field (public or private)
- `get_public_field_type_info/2` - Looks up only public fields

Both return `{type, constraints}` tuples, with `{nil, []}` for unknown fields.

### AshTypescript.TypeSystem.ResourceFields.get_aggregate_type_info/2 (function)

Gets the resolved type for an aggregate field.

Aggregates can have computed types based on the underlying field type.
This function returns the fully resolved aggregate type.

### Examples - AshTypescript.TypeSystem.ResourceFields.get_aggregate_type_info/2 (function)

iex> get_aggregate_type_info(MyApp.User, :todo_count)
    {Ash.Type.Integer, []}

### AshTypescript.TypeSystem.ResourceFields.get_field_type_info/2 (function)

Gets the type and constraints for any field on a resource.

Checks attributes, calculations, relationships, and aggregates in order.
Uses non-public Ash.Resource.Info functions to access all fields.

### Examples - AshTypescript.TypeSystem.ResourceFields.get_field_type_info/2 (function)

iex> get_field_type_info(MyApp.User, :name)
    {Ash.Type.String, []}

    iex> get_field_type_info(MyApp.User, :todos)
    {{:array, MyApp.Todo}, []}

    iex> get_field_type_info(MyApp.User, :unknown)
    {nil, []}

### AshTypescript.TypeSystem.ResourceFields.get_public_field_type_info/2 (function)

Gets the type and constraints for public fields only.

Checks public attributes, calculations, aggregates, and relationships in order.
Used for output formatting where we only want publicly accessible fields.

### Examples - AshTypescript.TypeSystem.ResourceFields.get_public_field_type_info/2 (function)

iex> get_public_field_type_info(MyApp.User, :name)
    {Ash.Type.String, []}

    iex> get_public_field_type_info(MyApp.User, :private_field)
    {nil, []}

### AshTypescript.TypeSystem.ResourceFields.resolve_aggregate_type_info/2 (function)

Resolves aggregate type info including constraints.

For `first` aggregates with nil type, we need to look up the field on
the destination resource to get the actual type and constraints.

### Examples - AshTypescript.TypeSystem.ResourceFields.resolve_aggregate_type_info/2 (function)
